# 算力比较与每半小时 GPU 任务分析

## 入口与权限

- `/analysis`：完整页面，顶部为 A100 / RTX 4090 / RTX 5090 的最新任务分析。

## 性能比较的含义

CPU 图提供一次性 **SHA-256 单线程微基准**（1 MiB，3 次 × 0.6 秒，取中位数 MiB/s）和实际逻辑线程/vCPU 数量。测试以低优先级执行，未运行全核压测。Linux 使用 Python hashlib/OpenSSL，Windows 使用 .NET SHA256Cng；SHA 指令、软件实现、操作系统和当前负载都会影响结果。它不是整数、编译、仿真或 AI 数据加载的综合性能排名，不能按线程数推算多核成绩。

七台 CPU：A100 为双 Xeon Gold 6330（112 线程）；4090 为 Xeon Platinum 8375C（128 线程）；5090 为 Xeon Platinum 8457C（192 线程）；3060 Ti 为 i7-12700K（20 线程）；Windows 为 i7-4790K（8 线程）；PRO 6000 为 Ultra 9 285K（24 线程）；腾讯云仅获配 2 vCPU，不能把 EPYC 宿主机的 64 核算入。

PRO 6000 在本次部署时 SSH 隧道离线：硬件清单取最近有效快照，CPU 基准未测，不填零或编造分数。以后机器恢复，可运行 `scripts/cpu-microbench.py`，由管理员把结果合入服务数据目录的 `cpu-benchmarks.json`；不对网页开放压测入口。

GPU 图比较同精度 **FP32 普通 CUDA 理论峰值**，可切换单卡与整机；另图比较标称显存。整机 FLOPS 是乘 GPU 数量的理论合计，不是实测线性加速，整机显存也不能自动合并。A100 的混合精度、HBM、NVLink 优势不能用这张 FP32 排序替代。

## 采集与 AI

`gaasd-analysis.timer` 在腾讯云按北京时间每小时 00、30 分运行，并在开机 2 分钟补启动；Persistent 补做错过的触发。`analysis_collector.py` 使用文件锁和半小时槽去重，避免页面访问、重启或重复启动造成重复调用。三台合并一次 AI 请求，输出限制 2,400 tokens，关闭思考模式，不自动重试付费请求。

采集沿用受限 SSH 密钥及严格 known_hosts 校验，三个固定目的地：

- A100：`aiusr@192.168.2.201:2202`，原 OpenVPN。
- 4090：`centos@127.0.0.1:2225`，Windows 中转。
- 5090：`user001@127.0.0.1:2223`，Windows 中转。

新增受限命令 `workloads`，原 `snapshot` 不变。探针读取约 5 次 GPU 采样、GPU 进程和少量繁忙 CPU 进程，选定工作负载参数、用户、运行时长，以及有权限读取的进度字段。不会读取环境变量、私钥、任意文件或整段日志。命令参数采用白名单，密码、token、URL 等过滤；shell 脚本主体不发送。进程命令及日志均作为不可信数据，AI 无工具和执行权限，前端用 textContent 显示，不能执行模型生成的 HTML。

远端探针安装位置为各用户 `~/.local/share/gaasd-status/current`（A100）或 `~/.local/share/gaasd-fleet/current`（4090/5090）；新增 `workload_probe.py`，更新对应 `status_probe.py` / `fleet_probe.py` 的两个固定命令分支。安装前保留 `before-analysis-20261025T144950` / `...144952` / `...144954` 备份。未修改授权密钥与隧道。

AI 只按证据判断任务；数秒 0% 不能判定卡死或空闲。采集失败沿用上次证据并显示时间；AI 调用失败保留上次分析及原分析时间。全部离线不调用 AI。历史保存 7 天（最多 336 轮），用量月账保留 24 个月。最新分析超过 40 分钟显示过期。

## 模型、密钥与费用

本任务使用 `D:\Code\GAASD-Web\.env` 的 `GAASD_AI_LLM_API_KEY` 和 `GAASD_AI_LLM_BASE_URL`。原文件及 `GAASD_AI_CHAT_MODEL=glm-5.1` 不变。专用模型为已验证可调用的 `qwen3.7-plus`：选择依据是任务识别能力与成本平衡，不声称其能力超过 Max 系列。

云端配置 `/etc/gaasd-analytics/analysis.json`，权限 **0640 root:gaasd-analytics**；密钥不提交 Git、不返回前端、不写入日志。模型调用仅允许北京 `https://dashscope.aliyuncs.com/compatible-mode/v1`。

非敏感配置模板（密钥需通过安全通道填入）：

```json
{
  "base_url": "https://dashscope.aliyuncs.com/compatible-mode/v1",
  "api_key": "从用户授权的本地 .env 安全转移，不在文档中填写",
  "model": "qwen3.7-plus",
  "directory": "/var/lib/gaasd-analytics/analysis",
  "input_cny_per_million": 2,
  "output_cny_per_million": 8
}
```

[百炼官方价格](https://help.aliyun.com/zh/model-studio/model-pricing)：北京、输入不超过 256K 的原价为输入 ¥2/百万、输出 ¥8/百万；页面另列限时 8 折，预算保守按原价，不扣免费额度和缓存折扣。

- 48 次/天 × 30 天 = **1,440 次/月**（每轮包含三台）。
- 前两次真实调用：分别输入 7,099 / 7,177、输出 883 / 849 tokens，共 16,008 tokens，原价共 ¥0.042408。按两次均值推算月输入 10.279M + 输出 1.247M，约 **11.526M tokens / ¥30.53**；实际用量随任务数量和说明长度变化。
- 保守示例：每轮输入 8,000、输出 1,800，则月输入 11.52M + 输出 2.592M，约 **14.112M tokens / ¥43.78**。
- 单次无重试；每次 API 返回 usage 都入账，包括输出格式校验失败。网络失败若未得到 usage，供应商可能计费而本地无法精确记录，所以网页金额明确为估算，以百炼账单为准。

## 构建、部署与回退

`npm run build:analysis -- YYYYMMDDTHHMMSS` 只打包代码、页面和 systemd/Nginx 模板，带 SHA-256 清单。上传归档和 `scripts/deploy-analysis.py` 后在腾讯云以 root 运行部署脚本。它复制当前后端到新版本，仅覆盖本功能文件，保留前端、数据库、生产凭据及原后端；验证认证后增加 Nginx 路由、启用计时器。

持久数据目录 `/var/lib/gaasd-analytics/analysis`（0700 gaasd-analytics），包括 `inventory.json`、`cpu-benchmarks.json`、`latest.json`、`history/*.json`、`usage.json`。重新部署不清空数据。Git 只包含代码、测试和说明；运行数据在 `work/` 与服务器目录中，不提交。

常用检查：

```bash
systemctl status gaasd-analysis.timer
systemctl list-timers gaasd-analysis.timer
journalctl -u gaasd-analysis.service -n 20 --no-pager
sudo -u gaasd-analytics cat /var/lib/gaasd-analytics/analysis/latest.json
```

回退：停止并禁用 `gaasd-analysis.timer`；按 `/var/backups/gaasd-analysis-版本/deployment.json` 恢复后端 current 链接、备份的 Nginx snippet，执行 `nginx -t` 后 reload，并重启 gaasd-analytics。数据与旧版本保留。若恢复探针，用上述各主机备份覆盖对应入口；新 workload 模块可以保留，不会被原入口调用。
